# mcpcls 项目总结（截至 2026-10-16，T-001 → T-028）

这份总结用来交付：现在默认能做到什么、每个数字有多可信、试过哪些路、哪些走不通、还剩什么问题。
所有数字都来自仓库里已落盘的报告，每条后面附了出处。

## 1. 一句话现状

线上默认是一条**纯 tfidf、离线可跑、单请求约 3 ms** 的链路：判断要不要调用工具（need），给出能力域，
再从 2405 个真实 MCP 工具里取 Top-5 候选，并给工具标风险等级，L3 要用户确认。
低置信度的请求可以交给 Jev（TypeSafe）兜底。另有一个**可选的语义重排**，开了以后中文检索能涨约 7 个点，默认关。

## 2. 当前默认的可信数字

主口径：走完整 `route`，need 判错的请求检索直接计 0。开发折 = 5 折里的第 0–2 折，测试折 = 第 3–4 折，数据是 600 条 BFCL 真实请求。

| 指标 | 数值 | 可信度 | 出处 |
| --- | --- | --- | --- |
| 中文严格 R@5（开发折 / 测试折） | 37.5% / 32.0% | 金标工具来自 BFCL 原数据，可信 | `reports/eval_current_default.md` §1 |
| 英文严格 R@5（开发折 / 测试折） | 63.8% / 57.2% | 同上 | 同上 |
| need 需要工具召回 / 精确率（参考集 200 条） | 75.5% / 94.9% | 参考集 = Claude 预标 + gu 抽查（D-005） | `reports/eval_reference.md` §1 |
| 能力域主域准确率（参考集 147 条） | 40.8% | 同上；银标上是 62%，但银标和训练标签出自同一对打标模型，偏高 | `reports/eval_reference.md` §3；`reports/eval_t028.md` |
| 风险：L3 被判低（参考集 28 个 L3） | 0 个（T-023 之后） | 同上 | `.collab/reviews/T-023.md` |
| 端到端延迟 p50 / p95 | 2.5 ms / 3.4 ms | 随机器负载变化 | `reports/eval_current_default.md` §5 |

**最该记住的两点**：
- 中文检索比英文低 20 多个点，原因是 tfidf 对中文只能用字符 n-gram。这是现在最大的短板，见第 3 节的可选重排。
- 能力域准确率只有约四成，但它目前**只影响输出字段**，不影响检索和 need（软过滤默认关）。

## 3. 可选增强：语义重排（T-025，默认关）

召回仍用 tfidf；对 Top-50 用语义模型打分，再和 tfidf 分线性融合。测试折数字（只报过一次）：

| 档位 | 参数 | 中文严格 R@5 | 英文严格 R@5 | 重排 p95 | 额外依赖 |
| --- | --- | --- | --- | --- | --- |
| 默认（关） | — | 31.5% | 55.6% | — | 无 |
| 主选 | `--rerank BAAI/bge-m3 --rerank-n 50 --rerank-fusion linear --rerank-alpha 0.5` | 39.1% | 59.5% | 约 150 ms | sentence-transformers + 4.6 GB 模型 |
| 轻量 | `--rerank intfloat/multilingual-e5-small --rerank-n 50 --rerank-fusion linear --rerank-alpha 0.3` | 37.8% | 58.8% | 约 20 ms | sentence-transformers + 470 MB 模型 |

（这张表的基线 31.5% / 55.6% 是 T-025 报告里的测试折复算值，和上表快照里的 32.0% / 57.2% 口径略有不同，以 `reports/eval_t025.md` §2 为准。）

默认不开，是因为默认部署要保持零模型依赖（D-007，T-016/T-019 的方向）。部署方需要更好的中文检索时，开轻量档即可。

## 5. 采用了的改动（按对默认的影响排序）

- **双语索引**（T-011）：中文严格 R@5 10.2% → 48.4%（当时的口径），是到目前为止最大的一次提升。
- **真实工具目录作为默认**（T-010/T-012）：2405 个工具，双路打标的银标。
- **软 need 阈值 0.7**（T-020）：判成 none 但置信度不高的请求也附带候选，中文主口径 26.0% → 37.5%。
- **Jev 低置信度兜底**（T-004/T-005）：本地模型低于阈值的约 17% 请求交给 Jev。
- **风险规则补信号**（T-023）：参考集 L3 漏判 2 → 0。
- **第二路打标换成 DeepSeek**（T-017）：主指标和 Haiku 分不出差别，成本更低。

## 6. 剩下的问题（没有承诺要做）

1. **中文检索**：默认链路只有三成多。要再往上，要么默认开重排（会引入模型依赖），要么改进中文索引文本。
2. **能力域约四成**：可信的评估集（参考集）只有 147 条，而且只能用来报告。真要改进，需要另标一份**请求级**选参集，这要花 LLM 额度；它对检索没有帮助。
3. **银标偏差**：工具域、风险、请求标签都来自 Jev + Haiku/DeepSeek 的两路一致，会偏向这几个模型。参考集也只是"Claude 预标 + gu 抽查"，不是纯人工金标。
4. **样本量**：开发折 1 条 = 0.28 个点，参考集 1 条 = 0.68 个点。小于 2–3 个点的差别基本都是噪声。
