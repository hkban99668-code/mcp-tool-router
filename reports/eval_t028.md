# 能力域投票重评:改用请求级银标选参(T-028)

T-027 用 BFCL"金标工具的银标域"当选参标签,与候选投票同源,开发折 +59 点是循环评估(`.collab/reviews/T-027.md`)。本卡把同一组候选(D0/D1/D2)原样搬到**请求级**银标`data/v3-primary/real_train.jsonl`(need≠none)与 `real_holdout.jsonl` 上重评。

> 显式设置:分类头与检索都按线上默认(tfidf,双语索引,软过滤关,软 need 0.7,top_k=5);投票只在检索 Top-k 的 `domains` 上做,**不反馈进检索**。选参集全部 5 折折外;留出集与参考集各只报一次。

> 1 条样本 = 1/319 = 0.31 个百分点(选参集)。

> 复跑说明:标 ms 的数字(投票延迟)两次运行会变,其余数字逐字节相同;置信区间固定种子 bootstrap 1000 次。


## 0. 调查结论

**(1) 与参考集去重**:参考集 `data/gold_candidates_claude.csv` 200 条,与 `real_train` / `real_holdout` 按 **id** 与**规范化文本**(NFKC + 去空白 + 小写)各查重叠,任一命中即剔除。

| 集合 | 原行数 | 剔除后 | 剔除条数(need≠none) |
| --- | --- | --- | --- |
| `real_train` | 936 | 936 | 0 |

`real_train` 与参考集**无任何重叠**(id 0 条、规范化文本 0 条);`real_holdout` 有 100 条与参考集同 id 且同文本,全部剔除。所以选参集未变(need≠none 319 条),留出集从 80 条 need≠none 削到 29 条,后者样本很小。

**(2) 选参集(剔除后的 real_train need≠none)分布与多数类基线**

- **多数类基线**(永远猜最常见的域 `search_web`):主口径 23.5%(75/319)。

**(3) 标签偏差:单主域 vs 参考集的多域口径**

`real_train` 的 `domains` 是 Jev + Haiku 两路**一致的主域**(primary 口径,单个域,实测 319/319 条单域);参考集是 Claude 预标 + gu 抽查的**请求级**标签(其中若干条多域)。两者都按请求文本打,不是工具银标,但口径不同:

- 主口径 = "预测分布 argmax ∈ 金标域"。在**单主域**标签上它退化成 top-1 准确率(argmax 必须正好等于那个主域);在**多域**参考集上,argmax 落进任一域就算命中,分母相同的多域行更容易得分。所以同一方法在选参集上的主口径与在参考集上的**不可直接比大小**。

- `real_train` 的域是**两路一致**的子集,可能偏向模型更常达成一致的常见域(如 `search_web`),对不常见的域有低估。

## 4. 结论

- 选参集上主口径最高的是 **D2 融合 k=10 β=0.7**:65.5% vs D0 62.1%(+3.4 个点);改默认门槛 = ≥ 4 个点。

- 留出集上主选 65.5% vs D0 62.1%(+3.4 个点);门槛要求"不比 D0 低"。

- 参考集(请求域、可多域)上主选 43.5% vs D0 40.8%(+2.7 个点)。

- **不建议改默认**:选参集只高 3.4 个点(< 事先定的 4 点门槛)。`domains` 仍由能力域头出,Router 没接投票,`cli evaluate` / `cli route` 输出与改前逐字节一致(只有延迟会变)。未达门槛的收益视为**不能作为改默认依据**。

- 本卡只改选参标签、不改线上代码:候选与实现复用 T-027 的 `domainvote` 与 `_t027_*`。改不改默认由 Claude 拍板后另立卡。
