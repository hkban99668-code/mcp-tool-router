# 金标候选表说明(data/gold_candidates.csv)

200 条真实请求,请逐条核对 `need / domains / actions` 三列:预填值大多数是对的,**只改错的**,改完把文件发回来即可(用 Excel 直接打开就行,文件带 BOM)。


## 每列是什么

| 列 | 含义 | 要不要改 |
| --- | --- | --- |
| id | 样本编号(`来源-序号`),用来回查原始数据集 | 不要改 |
| text | 翻译成中文的请求正文,模型看到的就是这一列 | 不要改 |
| text_orig | 数据集里的原文 | 不要改 |
| source | 来自哪个数据集(bfcl / apibank / alpaca_zh) | 不要改 |
| labeler1_name / labeler2_name | 两路各自的客户端名(第一路是 `--labelers` 里第一个,默认 Jev) | 不要改 |
| labeler1_need / labeler1_domains | 第一路(基准路)的判断 | 参考 |
| labeler2_need / labeler2_domains | 第二路的判断 | 参考 |
| local_need / local_domains | 本地模型的判断 | 参考 |
| need | **要核对的**:none / single / multi | 改错的 |
| domains | **要核对的**:能力域,多值用 `;` 分隔 | 改错的 |
| actions | **要核对的**:动作类型,多值用 `;` 分隔 | 改错的 |
| note | `need 不一致` / `主域不一致` 两个模型判断不同;`有一路没问到答案` 表示有一路当时没拿到结果 | 不要改 |

两路不一致的行怎么预填的:`need` 按本地模型的判断,`domains` 和 `actions` 按第一路(`--labelers` 里第一个,默认 jev)的判断,两路的原始判断都留在 `labeler1_*` / `labeler2_*` 那几列里可以对照。觉得都不对就直接改成你认为对的。


## 类别定义(取自 `taxonomy.py`,改表时以这里为准)

## 能力域 domains(多选)
- file:文件与文档。读写本地文件、云盘文件,解析 PDF/Office 文档 例:读取 report.pdf;把这段内容保存成 notes.md 边界:Wiki/笔记类内容归 knowledge;代码仓库里的文件归 code
- code:代码与开发。Git 仓库、Issue/PR、CI、包管理 例:给这个仓库开个 PR;看看 CI 为什么挂了 边界:执行任意 shell 命令归 system_misc
- database:数据库与数据分析。SQL 查询、数仓、表格计算 例:查一下上个月订单量;建一张用户表
- search_web:搜索与网页。网页搜索、抓取网页内容、学术检索 例:搜一下最新的 MCP 规范;抓取这个网址的正文 边界:需要点击、登录、填表的网页操作归 browser
- browser:浏览器与自动化。操作浏览器、点击填表、截图、RPA 例:打开官网帮我点登录;给这个页面截个图
- comms:通讯协作。邮件、即时消息、会议 例:给张三发封邮件;在 #dev 频道发个通知
- calendar_task:日程与任务。日历、待办、项目管理任务 例:明天下午三点约个会;建一个待办提醒我交报告
- knowledge:知识库与笔记。Wiki、笔记、内部知识库检索 例:在 Notion 里找上周的周报;把会议纪要记到知识库
- cloud_ops:云与运维。云资源、容器、监控告警 例:把 api 服务扩到 3 个副本;看下 pod 日志
- business:业务系统。CRM、电商、支付、工单 例:给这个订单退款;查一下客户 A 的跟进记录
- media:多媒体。图片/音频/视频的生成与处理 例:画一张猫的插画;把这段音频转成文字
- weather_geo:天气地图与出行。天气预报、地图与地点查询、导航路线、航班火车与打车等出行查询和预订 例:北京明天天气怎么样;查一下从机场到酒店怎么走 边界:订酒店、买票付款的订单管理归 business;只是查信息归这里
- entertainment:娱乐资讯与推荐。影视、音乐、体育、游戏、演出的信息查询与推荐(查片单、找歌、看比分、查演出) 例:推荐几部最近的科幻片;湖人昨晚比分多少 边界:生成或处理图片音视频归 media;购票付款归 business
- system_misc:系统与其他。Shell、本地系统、设备控制等以上都不属于的通用工具 例:运行 ls -la;把空调调到 26 度
## 动作类型 actions(多选)
- read:只读查询。只读取或检索信息,不改变任何状态
- create:新建。新建一条记录、文件、资源
- update:修改。修改已有的记录、文件、资源,可撤销
- delete:删除。删除或覆盖数据,通常不可撤销
- execute:执行。运行代码、命令、部署、脚本
- send:对外发送。发消息、发邮件、发布内容、付款,对外部产生影响
## 是否需要 MCP need(单选)
- none:不需要。LLM 直接回答即可,不需要调用任何 MCP 工具
- single:单工具。需要调用一个 MCP 工具
- multi:多工具。需要组合调用多个 MCP 工具
